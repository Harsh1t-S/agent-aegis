## Bugs fixed locally

| Problem | Consequence | Fix |
| --- | --- | --- |
| Provider-specific key lookup fell back to another provider's key | Invalid credentials sent to the wrong service; the prior PR's own regression test failed | Bind generic credentials to their configured endpoint; skip providers without a usable key |
| Dashboard ignored the server's `LLM_MODEL` and used a hardcoded mixed pool | Runs could keep using Groq/Google after a configuration change | Resolve defaults centrally and persist the selected pool in each version |
| Tool results were converted into user messages and truncated | Changed the authority of injected content and removed evidence from the conversation | Send native tool messages with matching tool-call IDs and complete results |
| Only the first returned tool call was executed | The model's remaining actions disappeared | Queue every returned call for the engine to execute |
| Retry handling assumed numeric Retry-After and ignored transport failures | Retryable provider failures could terminate a scenario prematurely | Handle HTTP dates, malformed values, bounded delays, and transport retries |
| Empty/truncated completions were treated as answers | A partial response could be scored as agent behavior | Mark unusable completions as execution errors |
| Missing provider configuration was discovered after persisting a suite | Orphaned versions and failed runs | Check credentials before creating the suite and return an actionable 503 |
| Invalid adapter names silently selected the behavioral stand-in; scenario counts were unbounded | Wrong agent tested or excessive work queued | Validate adapter, version label, HTTP URL presence, and 1–10 scenarios per category |
| Execution errors disappeared from list/detail reports | Zero-test evaluations stayed queued; partial scores could pass CI | Preserve error traces, show error totals, use a terminal failed state, and block CI |
| Progress polling used setInterval regardless of response time | Overlapping serverless workers and stale responses | Poll after the previous request finishes; atomically claim pending runs |
| Provider calls could outlive the engine deadline | Vercel could kill a request before it saved progress | Enforce an async deadline and drain one remote scenario per invocation |
| Guardrail POST executed the entire ladder synchronously | Long ladders could exceed the function lifetime | Queue all probes before draining; subsequent report polls continue execution |
| Old successful guardrail attempts hid newer pending/failed attempts | Stale resistance results appeared current | Prefer active/latest attempts and report pending probes separately |
| Replays and the internal ladder route used the edited agent's current policy | Historical versions could be tested against later instructions | Use the version's saved prompt and tool schema |
| Nested MCP `{result: {tools: [...]}}` imports were misread | Imported a tool called `tools` instead of the actual tools | Repeatedly unwrap supported envelopes |
| Route changes retained the previous resource's data during loading | Old agent/report data could appear on a different page | Reset loading/data on resource changes and ignore obsolete responses |
| Landing page substituted zero when no score was available | Missing data displayed as “Unreliable” | Show unavailable/loading state and choose a completed evaluation |
| Settings reset toast said behavioral mode while selecting the real model | Misleading confirmation | Match the actual defaults |
| Local Vite defaulted to the production API | Local testing could mutate the live demonstration | Default development proxy to the local backend |

## Authorized release follow-up

The user subsequently requested that all fixes be pushed, with AIRouter as the
primary provider and the existing providers retained for fallback.

- **Public write access fixed:** all deployed mutation routes require the separate
  `AEGIS_ADMIN_KEY`. Public progress, ladder and trace reads cannot execute queued
  work. Raw legacy configuration reads require owner access too. The Settings
  page validates the owner key before keeping it in this tab. A missing owner key
  leaves production read-only; local development remains usable.
- **Preview routing fixed:** the frontend now proxies API traffic through a Vercel
  function using an environment-specific `AEGIS_API_ORIGIN`. Previews with missing
  configuration or a known production API alias return a configuration error.
- **AIRouter primary with backups:** the first model is tried on every scenario;
  scenario IDs no longer rotate the primary. Existing Groq/Google credentials are
  used only on primary failure. Invalid keys, insufficient credits, missing models,
  transport failures, rate limits and server errors permit fallback; malformed
  requests still fail. Model provenance remains in the stored trace.
- CI requests now support the owner authorization header and use the server's
  configured model order instead of hardcoding a Groq/Google pool.
- CI waits for queued guardrail probes to finish before applying the resistance gate.
- The newer upstream README edit was merged before preparing the release.

Release checks: **310 Python tests** and **18 frontend tests**; TypeScript,
ESLint (zero errors) and the production build pass. Provider calls use synthetic
credentials and mocked responses in tests.

The remaining user setup is to paste the real `AIROUTER_API_KEY` and a separate
random `AEGIS_ADMIN_KEY` into the backend's Production environment, keep the
existing fallback keys/database configuration, and redeploy. The README contains
the exact environment block and Settings instructions. Real AIRouter inference
cannot be verified until that key is configured.

This is a targeted code and deployment audit, not an assertion that every route,
